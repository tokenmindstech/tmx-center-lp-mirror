# Sync prompt: update TMX Center from "TMX Center Website"

Use this whenever the `TMX Center Website/` folder has been updated and the deployed TMX
Center hub at the repo root needs to be refreshed. Copy everything in the block below and
paste it into Claude Code, run from the repo root.

---

Update the deployed TMX Center hub at the repo root to the latest version in the
`TMX Center Website/` folder, and link all the required files (html, js, css, images).

**Rules**

- `TMX Center Website/` is the read-only source of truth. Never edit, move, or delete it
  or anything inside it. Only copy out of it. (It has gone missing between sessions before;
  if it is not present, stop and say so rather than syncing from stale files.)
- Do not assume the file list, or the exact link strings, from the last run. Re-derive both
  from the source every time. The source is regenerated by a design tool and changes shape
  between syncs, it has already shipped three different link schemes for the same nav.
- Copying over / replacing files at the root is fine.

**Step 1: re-derive the dependency graph from the source**

TMX Center is a single self-contained page, unlike the multi-page Visibility site. Confirm
that is still true, then collect its dependencies:

- Page: `TMX Center Home.dc.html` (served at `/`, see step 5).
- Component imports: the home page's `<x-import>` tags resolve to the design-system bundle
  (`component-from-global-scope="TMXLPWebsiteDesignSystem_...Button"` etc., provided by
  `_ds_bundle.js`) and to the `image-slot` web component (`from="./image-slot.js"`). These
  are NOT `.dc.html` component files, so there are no header/footer partials to copy. If a
  future export adds a `<dc-import>` or an `<x-import>` that resolves to a `<name>.dc.html`,
  copy that file to the root too.
- Internal nav: every `href="....html"`. As of this run there are none, the source ships
  absolute URLs (see step 3).
- JS: `support.js`, `image-slot.js` (referenced as `./support.js`, `./image-slot.js`).
- CSS + design system: `_ds/<design-system-id>/styles.css`, the four `tokens/*.css` files
  (colors, effects, fonts, typography), and `_ds/<design-system-id>/_ds_bundle.js`.
- State: `.image-slots.state.json`.
- Images: every `assets/...` reference. As of this run that is only
  `assets/hero-scene-light.png`. Re-grep, do not trust this list, a stale list silently
  ships missing images.
- Remote images (an Unsplash hero photo) have no local file, leave them.
- Report any source file that nothing references, and skip it. As of this run those were
  the full Visibility site (`TMX Visibility.dc.html`, `Visibility Header/Footer/About/
  Features/Pricing.dc.html`, `TMX Visibility Pricing.html`), the `skill/` folder, and the
  `uploads/` folder. Those belong to the separate Visibility deployment, not to this hub.

**Step 2: copy into the repo root, overwriting**

- `TMX Center Home.dc.html`, plus any other `.dc.html` page/component the graph now names
- `support.js`, `image-slot.js`, `.image-slots.state.json`
- every referenced `assets/*`
- `_ds/` only if it differs from the source, it has been identical on every run so far

Practically, only `TMX Center Home.dc.html` usually changes. Diff the rest and copy only
what differs, but always re-derive rather than assume.

**Step 3: reapply the TMX Center link fix, required on every sync**

The source ships the three product nav links pointing at whatever the design tool currently
emits (past runs: local `.dc.html` files; this run: `www.tmx.center` on-page anchors and
`www.visibility.tmx.center`). The deployed hub must instead send each product to its own
marketing subdomain. The copy in step 2 overwrites this fix every time, so it always has to
be redone. Re-grep for the current form of each link, then repoint by destination:

- TMX Visibility  -> `href="https://visibility.tmx.center/"`
- TMX UGC         -> `href="https://ugc.tmx.center/"`
- TMX KOL         -> `href="https://kol.tmx.center/"`

Each product name appears three times: the products dropdown, the mobile nav, and the
footer. That is nine links total. Change only the href, never the visible link text, and do
not touch the `onClick` handlers (`closeProducts` / `closeMobileNav`).

Leave these alone (they are correct or out of scope for this fix):

- The hub self-links and same-page anchors (`https://www.tmx.center/`, `#faq`, `#products`).
- The login / register portals. Note an open discrepancy: the source currently ships
  `https://app.visibility.tmx.center/login` and `/register`, while the project convention in
  `CLAUDE.md` records the Visibility portal as `https://visibility.tmx.center/login`. Do not
  silently rewrite these, surface the mismatch and let the operator decide. UGC and KOL
  portals (`ugc.tmx.center/auth/login`, `kol.tmx.center/login`) match the convention.

**Step 4: verify and report**

- No product nav link still points at `www.tmx.center/#tmx-ugc`, `www.tmx.center/#tmx-kol`,
  `www.visibility.tmx.center`, or any local `*.dc.html` file. All nine resolve to the three
  per-module subdomains above.
- Every local reference from the home page resolves to a file that exists at the root:
  `support.js`, `image-slot.js`, every `assets/...`, and every `_ds/...` css/js file.
- Serve the root locally and confirm the page, `support.js`, the `_ds` bundle, and any new
  images all return 200.
- Report the login/portal discrepancy from step 3 if it is still present.

**Step 5: leave `vercel.json` alone unless the structure changed**

The existing config already covers this setup: `/` rewrites to `TMX Center Home.dc.html`,
and the `*.dc.html` header rule automatically covers every page and component. Vercel serves
all static files without registering them. `cleanUrls` must stay `false`.

**Context and gotchas**

- The hub is a single page. There are no header/footer partials to copy, its nav and footer
  are inline in `TMX Center Home.dc.html`, so the link fix in step 3 lives in that one file.
  If the site later splits into multiple pages that import shared partials, the fix must be
  reapplied to every deployed page, and `support.js` fetches partials as `<name>.dc.html`,
  so those component files must sit at the root next to the pages.
- Filenames contain spaces (`TMX Center Website`, `TMX Center Home.dc.html`). Quote every
  path, and use `while IFS= read -r` rather than a bare `for` loop, which splits on spaces
  and reports false broken links.
- The source folder also contains the entire Visibility marketing site. Do not deploy those
  files from this repo, this root is only the TMX Center hub. They are synced separately.
- Copy style convention (`CLAUDE.md`): never introduce em dashes into site copy, and never
  add a trailing period to a section heading. This matters only if you touch copy, not for a
  pure file sync.
